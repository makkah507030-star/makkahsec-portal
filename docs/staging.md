# النسخة التجريبية

نسخة كاملة من البوابة على **https://makkahsec-staging.netlify.app**، بقاعدة بيانات
منفصلة (مشروع Supabase باسم `makkahsec-staging`) فيها مدرسة وهمية. تُجرَّب فيها
التحديثات **قبل** دمجها في `main`، ولا يصل منها شيء إلى المستخدمين الحقيقيين.

- الكود نفسه من المستودع نفسه؛ يختلف فقط موقع Netlify وقاعدة البيانات.
- تظهر في أسفل كل صفحة شارة «نسخة تجريبية — بيانات وهمية».

## الحسابات التجريبية

كلمة المرور لكل الحسابات: `Mk@Staging-1448`

| الحساب | رقم الهوية |
|---|---|
| الدعم الفني | `9000000001` |
| مدير المدرسة | `9000000002` |
| معلم الرياضيات (الصفوف الثلاثة) | `9000000011` |
| معلم اللغة العربية (الصفوف الثلاثة) | `9000000012` |
| معلم الكيمياء (الثاني والثالث) | `9000000013` |
| معلم الفيزياء (الثاني والثالث) | `9000000014` |
| طالب (فصل 101) | `9000000101` |
| ولي أمر (للطالب نفسه) | `9000000201` |

المدرسة: ثلاثة فصول (101 و201 و301)، في كل فصل أربعة طلاب، وحصة رياضيات وحصة
عربي في كل يوم دراسي. أرقام الهوية تبدأ بـ 9 فلا تتعارض مع أي رقم حقيقي.

## النشر

- **تلقائيًا:** كل دفع إلى فرع `claude/...` يُنشر على الموقع التجريبي (سير العمل
  **نشر النسخة التجريبية**). آخر دفع يحلّ محل ما قبله.
- **يدويًا:** Actions ← نشر النسخة التجريبية ← **Run workflow** ← اختر الفرع.
- بعد التجربة يُدمج طلب الدمج في `main` كالمعتاد، فيُنشر على الموقع الحقيقي.

## الإعداد (مرة واحدة)

1. Supabase ← **New project** باسم `makkahsec-staging`.
2. الأسرار في GitHub (Settings ← Secrets and variables ← Actions):

   | الاسم | القيمة |
   |---|---|
   | `STAGING_DB_URL` | زر **Connect** ← **Session pooler**، مع كلمة مرور القاعدة مكان `[YOUR-PASSWORD]` |
   | `STAGING_SERVICE_ROLE_KEY` | Project Settings ← API Keys ← **service_role** / **Secret key** |

3. في موقع Netlify `makkahsec-staging` ← Environment variables:
   `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` للمشروع التجريبي، و`VITE_STAGING=1`.
4. رابط المشروع التجريبي في `STAGING_SUPABASE_URL` داخل
   `.github/workflows/staging-setup.yml`.
5. Actions ← **إعداد النسخة التجريبية** ← **Run workflow**.

## بعد إضافة ملف SQL جديد

**إعداد النسخة التجريبية** يعمل تلقائيًا عند دفع أي تعديل في `supabase/` إلى فرع
`claude/...`: يطبّق ملفات `supabase/*.sql` الأحدث من آخر تصدير للبنية، ولا يكرّر
البيانات الموجودة. البنية الكاملة لا تُعاد إن وُجدت.

## حماية القاعدة الحقيقية

أداة الإعداد تتوقف إن كان الرابط أو المفتاح يخص القاعدة الحقيقية، ولا تقرأ أسرار
القاعدة الحقيقية إلا للمقارنة. إشعارات الجوال الصادرة من القاعدة التجريبية تُوجَّه
إلى الموقع التجريبي لا إلى makkahsec.com.

## إن توقّف المشروع

Supabase يوقف المشاريع المجانية بعد أسبوع بلا استخدام. افتح المشروع واضغط
**Restore project**؛ البيانات لا تضيع.
