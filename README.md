# بوابة مكة الثانوية الرقمية

واجهة الويب للبوابة. مبنية بـ React + Vite، وتتصل بقاعدة بيانات Supabase.

---

## أولًا: التشغيل على جهازك

### 1) افتح موجّه الأوامر داخل مجلد المشروع

في ويندوز: افتح مجلد المشروع، اكتب `cmd` في شريط العنوان أعلى النافذة، ثم اضغط Enter.

### 2) حمّل المكتبات (مرة واحدة فقط)

```
npm install
```

يأخذ دقيقة أو دقيقتين. سينشئ مجلد `node_modules` — لا تحذفه ولا ترفعه.

### 3) اضبط الاتصال بقاعدة البيانات

انسخ الملف `.env.example` وسمّ النسخة `.env` — بالنقطة في أوله.

افتحه بمحرر نصوص وضع فيه القيمتين من Supabase: **Settings ← API**

```
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOi...
```

استخدم مفتاح **anon public** فقط.
**لا تضع مفتاح `service_role` هنا إطلاقًا** — هو سرّي ويتجاوز كل الحماية.

### 4) شغّل الموقع

```
npm run dev
```

سيظهر رابط مثل `http://localhost:5173` — افتحه في المتصفح.
الصفحة تتحدث تلقائيًا مع كل تعديل تحفظه.

للإيقاف: اضغط `Ctrl + C` في نافذة الأوامر.

---

## ثانيًا: النشر على Netlify

### الطريقة الأولى — رفع يدوي

```
npm run build
```

ينتج مجلد `dist`. اضغطه في ملف ZIP وارفعه على Netlify (خاصية Deploy manually).

**مهم**: ارفع محتوى `dist` لا مجلد المشروع كاملًا.

### الطريقة الثانية — ربط بـGitHub (أفضل)

ارفع المشروع على GitHub، واربطه من Netlify مرة واحدة.
ملف `netlify.toml` الموجود هنا يضبط كل شيء تلقائيًا.

بعدها كل تعديل يُنشر تلقائيًا، ولديك نسخ احتياطية وتاريخ للتغييرات.

**بعد الربط**، أضف المتغيرين في: Netlify ← Site settings ← Environment variables

```
VITE_SUPABASE_URL
VITE_SUPABASE_ANON_KEY
```

بدونهما سيُبنى الموقع لكن لن يتصل بقاعدة البيانات.

## ثالثًا: إنشاء أول حساب

الحسابات تُنشأ من Supabase، لأن إنشاءها من المتصفح يتطلب مفتاحًا سريًا.

### 1) أنشئ المستخدم في Supabase

**Authentication ← Users ← Add user**

- البريد: `1012345678@makkahsec.local`
  (رقم هويتك متبوعًا بـ`@makkahsec.local` — بريد داخلي وهمي، لا يُرسل إليه شيء)
- كلمة المرور: اختر واحدة
- فعّل **Auto Confirm User**

انسخ **UID** الظاهر بعد الإنشاء.

### 2) اربطه بالبوابة

في **SQL Editor** نفّذ (استبدل UID ورقم الهوية):

```sql
insert into public.users (id, username, role, must_change_pw)
values ('الصق-UID-هنا', '1012345678', 'admin', false);

insert into public.admin_roles (user_id, role_type)
values ('الصق-UID-هنا', 'principal');
```

### 3) ادخل

افتح البوابة وسجّل الدخول برقم الهوية وكلمة المرور.

## رابعًا: ترتيب الاستيراد

استخدم **قالب الاستيراد الموحّد** (ملف xlsx منفصل)، والترتيب إلزامي:

1. **الفصول** — 28 صفًا، مرة واحدة في السنة
2. **المعلمون**
3. **الطلاب وأولياء الأمور**

الملف يُقرأ **داخل متصفحك ولا يُرفع لأي خادم**. بعد الفحص تظهر معاينة بأعداد
الجديد والمحدّث والمرفوض والمفقود — راجعها قبل التنفيذ.

**السجلات المفقودة لا تُحذف أبدًا.** راجعها يدويًا وعطّل ما يلزم.

## ملاحظات مهمة

**الحماية في قاعدة البيانات لا في الواجهة.** سياسات RLS هي خط الدفاع الحقيقي —
إخفاء زر في الواجهة لا يحمي شيئًا. لا تعطّل RLS بأي حال.

**الدرجة غير المنشورة غير موجودة** بالنسبة للطالب وولي الأمر، لأن الشرط مكتوب
في سياسة قاعدة البيانات نفسها.

**تحضير المعلم مقيّد بتاريخ اليوم** على مستوى قاعدة البيانات. التصحيح بعد ذلك
يمر عبر الإدارة.

**ملف `.env` لا يُرفع على GitHub** — موجود في `.gitignore` أصلًا. تأكد من ذلك.

## ما لم يُبنَ بعد

- إنشاء الحسابات آليًا عند الاستيراد (يحتاج Edge Function بمفتاح الخدمة)
- استقبال بصمات ADMS من الأجهزة الأربعة
- إرسال الرسائل عبر تقنيات
- الاستئذان المسبق والملاحظات السلوكية
- التقارير والدرجات وملف الاعتماد والدعم الفني

الجداول والصلاحيات لكل ذلك **جاهزة في قاعدة البيانات** — ينقص بناء الشاشات.
